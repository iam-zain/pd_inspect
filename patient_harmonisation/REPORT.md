# Fixing the patient-level missingness leak: candidate comparison

All candidates use the unchanged `min16_lib` models (M1, M2, M3, LR meta-learner), the same
StratifiedGroupKFold 5 × 3 CV, cross-fitting, Youden threshold on training OOF and 2,000
patient-cluster bootstrap resamples. Only the harmonisation step and the training cohort differ.
Nothing outside this folder was modified. Re-run: `python run_candidates.py`, `python compare.py`,
`python pdonly_check.py` (Anaconda Python 3.13).

| Candidate | Harmonisation | Training cohort |
|---|---|---|
| A_visit_all | visit level (earlier approach) | all (721 patients) |
| B_patientvisit_all | patient level + visit level, 2 rounds (`ph_lib.harmonize_patient_level`) | all |
| C_visit_orig | visit level (= current sensitivity analysis) | original cohort (501) |
| D_patientvisit_orig | patient level + visit level | original cohort |
| E_none_orig | none | original cohort |

## Results

The current results (final model: M3 = collaborative filtering, handedness removed, inclusion
more than 15 of 30 items) are generated by `compare.py` in `comparison.md` / `comparison.csv`, and the
PD-only-wave check by `pdonly_check.py` in `pdonly_waves_sensitivity.csv`. Candidate D
(participant + visit harmonisation, original cohort) is the adopted pipeline: it has the lowest
or near-lowest missingness negative controls, specificity 0.775 vs 0.750 for the visit-level-only
pipeline A, and a lower Brier score (0.091 vs 0.107) on the 123 original-cohort test participants.
Earlier versions of this report described intermediate model versions and are superseded.
